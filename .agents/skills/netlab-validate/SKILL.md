# Проверить лабораторию

## Безопасность

Режим read-only. Не вызывать скрипты, которые перезаписывают .unl, без согласованного отдельного режима Implementation. Не подключаться к реальной сети. Не запускать fault injection без явного разрешения на учебном стенде.

## Процедура

1. Прочитать AGENTS.md, .agents/RULES.md, .agents/standards/LAB-STANDARD.md и документацию лаборатории; определить .unl/.gns3, стадии, типы узлов и утверждения о startup-config.
2. Выполнить: python3 .agents/tools/validate_netlabs.py --lab "путь/к/лаборатории". Либо --all для всего архива; --json для отчёта.
3. Для EVE-NG: проверить корректность XML, связи node/interface/network, config="1", наличие записей objects/configs, декодирование Base64. Сопоставить содержимое с исходными .cfg с учётом стадии/платформенного преобразования. **Обязательно выполнить существующие лаб-специфичные read-only проверки** (например, MPLS tools/validate_lab.py и tools/validate_startup_configs.py; DDoS tools/check_startup.py). Если их нет, явно указать ограничения общего валидатора.
4. Для GNS3: проверить JSON, node_id и концы линков, наличие самого проекта и не выдумывать готовые конфигурации из файлов .txt.
5. Проверить ссылки README, схемы, импорт, критерии успеха и обратимость сценариев. WARNING для отсутствующей документации у архивных проектов — не повод ломать исходники.
6. Реальные проверки L3/L4 проводить только при наличии изолированного стенда; сохранить команды и фактический вывод соседств, маршрутов, ping/traceroute и rollback.
7. Отчёт: ERROR, WARNING, что проверено статически, что реально запущено, что не проверено, рекомендации; не исправлять автоматически.

## Выход

Краткая таблица: проверка → PASS/WARN/FAIL/NOT RUN → свидетельство. Уровень зрелости L1–L4 подтверждается только соответствующими доказательствами.
