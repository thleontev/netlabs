# Оформить существующую лабораторию

## Вход и режим

Запрос «оформи», «приведи к стандарту», «сделай README» означает Documentation. Не редактировать .unl, .gns3, .cfg, UUID, топологию, адресацию и параметры протоколов.

## Процедура

1. Изучить AGENTS.md, LAB-STANDARD.md, README категории; сопоставить реальные файлы проекта, configs, схемы и существующие проверки.
2. Построить подтверждённую картину: узлы/образы из .unl/.gns3, фактические протоколы и линк-план из конфигураций, доступные сценарии. Не домысливать неподтверждённое.
3. Оформить лабораторный README по templates/lab-README.md: цель, превью схемы, архитектура, состав, файлы, быстрый старт, проверки, упражнения, ограничения. Удалять ссылки на отсутствующие файлы.
4. При необходимости добавить документацию IMPORT-RU.md, docs/EXERCISES.md, docs/DIAGNOSTICS.md, сценарии. Для неисправностей указать baseline, fault, rollback. Не скрывать различия платформ.
5. Привести README категории к стандартной таблице и кратким ссылкам; корневой README менять только если это требует задача/навигация.
6. Запустить общий валидатор и проверить diff; любые изменения .unl/.gns3/.cfg считать ошибкой scope (если не были отдельно разрешены).
7. Описать результаты и статус L1/L2/L3/L4, явно указать отсутствие runtime-проверки.

## Недопустимо

«Исправлять» настройки, менять имена QEMU-образов, незаметно включать startup-config, перерисовывать оригинал в ущерб точности и утверждать, что lab boot проверен при одном чтении файлов.
