# Создать лабораторию NetLabs

## Когда использовать

Пользователь просит разработать новую лабораторию или существенно дополнить сетевую функциональность существующей. Не использовать для задачи только оформления (см. netlab-document).

## Процедура

1. Изучить корневой AGENTS.md, .agents/RULES.md, .agents/standards/LAB-STANDARD.md, README целевой категории и одну близкую лабораторию. Проверить наличие похожих работ, чтобы не плодить дубликаты.
2. Описать учебную цель, платформу, образы, узлы, топологию, этапы, IP/AS/VRF/VNI и критерии проверки. Указать упрощения модели.
3. Создать отдельную папку в правильной категории. Применить шаблоны из .agents/templates/. Для новых устройств использовать configs/<DEVICE>.cfg; для стадий полные конфиги в 00-*, 01-* и так далее.
4. Создать .unl или .gns3 с согласованными ID/интерфейсами и проектными идентификаторами. Для EVE-NG встроить startup-config только там, где это поддержано; не считать наличие .cfg достаточным.
5. Создать PNG и по возможности SVG из одной сетевой модели. Обеспечить соответствие имён/линков/портов конфигурациям.
6. Подготовить README, инструкцию импорта, упражнения, диагностику, baseline и по необходимости fault/rollback сценарии.
7. Запустить общий валидатор и платформенные скрипты; для EVE-NG сравнить встроенные конфигурации с источниками с учётом необходимых преобразований. По возможности реально запустить на стенде и зафиксировать доказательства.
8. Обновить README категории и корня **только при фактическом добавлении** новой лаборатории. Описать статус L1–L4 и ограничения.

## Готово, когда

Проект структурно корректен, ссылки работают, наличие/отсутствие автозагрузки честно описано, у всех заявленных сценариев есть проверки и rollback; тесты/предупреждения документированы. Без реального стенда не утверждать L3/L4.
