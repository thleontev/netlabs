# 06 — Выключен локальный gateway SVI при работоспособном L2

**Этап:** 02  
**Задача:** показать, что потеря SVI затрагивает IP-routing хостов и не обязательно ломает одноимённый L2 VNI.

> Только изолированная лаборатория EVE-NG. Изменения применяются вручную к тестовым узлам. Команды не выполнять на рабочих сетевых устройствах. Конфигурации NX-OSv 9.3(x) и реальное поведение требуют проверки на образе.

## Baseline: докажи, что всё работает до сбоя

На LEAF-03: `show interface Vlan30`, `show ip route vrf TENANT1`. DB-C→DB-B и DB-C→CLIENT-A работают при корректно заданном default gateway.

Перед изменением сохрани вывод `show running-config`, таблицы маршрутизации и результат теста. Фиксируй время и симптом, а не только успешность ping.

## Внести неисправность

На **LEAF-03**:
```nxos
configure terminal
interface Vlan30
 shutdown
end
```

## Найти причину — control plane и data plane

- `show interface Vlan30` и `show ip route vrf TENANT1`: проверить исчезновение connected 192.168.30.0/24 и анонса соответствующего Type-5 с LEAF-03.
- DB-C (192.168.30.13) ↔ DB-B (192.168.30.12) в одном L2VNI 10030 **может продолжать работать**, так как L2 access + NVE не отключены.
- DB-C→CLIENT-A (другая сеть) должен перестать проходить через его локальный gateway, если MAC/IP не переключились на другое доступное gateway и не используются прежние ARP записи; фактический исход наблюдать.
- Не путать с изменением общей anycast MAC: её в этом сценарии **не меняем**.

## Откат

На LEAF-03:
```nxos
configure terminal
interface Vlan30
 no shutdown
end
```
Проверить anycast forwarding и IP route в TENANT1.
