# 12 — Изменение OSPF cost и перераспределение путей

**Этап:** 00 или 01  
**Задача:** проверить управляемый выбор underlay маршрута без выключения интерфейса.

> Только изолированная лаборатория EVE-NG. Изменения применяются вручную к тестовым узлам. Команды не выполнять на рабочих сетевых устройствах. Конфигурации NX-OSv 9.3(x) и реальное поведение требуют проверки на образе.

## Baseline: докажи, что всё работает до сбоя

LEAF-01: `show ip route 10.254.0.23`, `show ip ospf neighbors`. Зафиксировать текущую ECMP-картину и частоту трафика на обоих uplink.

Перед изменением сохрани вывод `show running-config`, таблицы маршрутизации и результат теста. Фиксируй время и симптом, а не только успешность ping.

## Внести неисправность

На **LEAF-01** повысить стоимость линка к SPINE-01:
```nxos
configure terminal
interface Ethernet1/1
 ip ospf cost 200
end
```

## Найти причину — control plane и data plane

- OSPF neighbor с SPINE-01 остаётся FULL, но `show ip route 10.254.0.23` должен предпочесть path с меньшей общей метрикой через SPINE-02 (при остальных настройках baseline).
- BGP EVPN по Lo0 может остаться Established к обоим RR через доступный alternate path; проверить, не путать BGP peer-path с forwarding ECMP.
- В capture на обоих underlay uplink сравнить фактические UDP/4789 потоки; их распределение зависит от хеша и числа flows.
- Обратный путь может иметь другую IGP cost и идти через другой Spine — это допустимая underlay асимметрия.

## Откат

На LEAF-01:
```nxos
configure terminal
interface Ethernet1/1
 no ip ospf cost
end
```
Вернуть предыдущее явно заданное значение, если оно было до эксперимента.

## Что объяснить в отчёте

Чем предпочтение пути по OSPF cost отличается от выбора BGP best path? Что из маршрутов на Spine указывает реальное направление VXLAN?
