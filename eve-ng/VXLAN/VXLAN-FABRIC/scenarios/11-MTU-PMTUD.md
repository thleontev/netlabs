# 11 — MTU/PMTUD через VXLAN

**Этап:** 02 (дополнительный Linux-вариант)  
**Задача:** измерить влияние VXLAN encapsulation на размер underlay IP пакетов и DF/PMTUD.

> Только изолированная лаборатория EVE-NG. Изменения применяются вручную к тестовым узлам. Команды не выполнять на рабочих сетевых устройствах. Конфигурации NX-OSv 9.3(x) и реальное поведение требуют проверки на образе.

## Baseline: докажи, что всё работает до сбоя

Нужны **два Linux-хоста вместо VPCS**, на Ethernet access LEAF-01/LEAF-03 (VLAN10/VLAN30). В текущем .unl их нет: заменить VPCS в копии лаборатории или создать Linux nodes вручную; IP/gateway сохранить как в README. На Linux проверить `ip -br link` и `ip route`. На NX-OS зафиксировать `show interface Ethernet1/1` и реальную L3 underlay MTU.

Перед изменением сохрани вывод `show running-config`, таблицы маршрутизации и результат теста. Фиксируй время и симптом, а не только успешность ping.

## Внести неисправность

Никаких деструктивных изменений в первой части. На Linux-источнике отправить ICMP c DF в пределах host MTU:
```bash
ping -M do -s 1200 -c 3 192.168.30.13
ping -M do -s 1472 -c 3 192.168.30.13
```
Затем при поддержке NX-OS **в отдельном эксперименте** настроить underlay MTU одного выбранного uplink ниже требуемого размера и повторить тест, предварительно сохранив исходный MTU. Синтаксис и допустимые значения проверять под свою NX-OSv.

## Найти причину — control plane и data plane

- Захват на uplink Leaf↔Spine: UDP/4789 и outer IP; IPv4 VXLAN добавляет ориентировочно 50 байт к внутреннему Ethernet frame (дополнительные VLAN tags увеличивают overhead).
- Для 1500-байтного внутреннего IP пакета обычный underlay требует порядка 1550 байт IP MTU. При маленьком underlay MTU большие пакеты могут теряться/фрагментироваться в зависимости от DF и реализации.
- `ping -M do -s 1472` отправляет IPv4 ICMP с 1500-byte IP packet (20 IP + 8 ICMP +1472) **на Linux**; VPCS эту опцию обычно не поддерживает.
- Не делать вывод по единичному ping; контролировать PCAP, ICMP fragmentation needed и размер outer frames. OSPF/BGP могут оставаться healthy.

## Откат

Убрать временную ручную MTU-настройку и восстановить **сохранённое исходное значение** (не угадывать default); повторить оба теста.
