# 04 — Ошибочный RT import на L2VNI 10020

**Этап:** 01  
**Задача:** продемонстрировать изолированную поломку одного виртуального сегмента при здоровом OSPF/BGP.

> Только изолированная лаборатория EVE-NG. Изменения применяются вручную к тестовым узлам. Команды не выполнять на рабочих сетевых устройствах. Конфигурации NX-OSv 9.3(x) и реальное поведение требуют проверки на образе.

## Baseline: докажи, что всё работает до сбоя

На LEAF-03 зафиксировать `show running-config evpn`; APP-A → APP-C работает (VNI10020), DB-B → DB-C (VNI10030) работает.

Перед изменением сохрани вывод `show running-config`, таблицы маршрутизации и результат теста. Фиксируй время и симптом, а не только успешность ping.

## Внести неисправность

На **LEAF-03** (контекст EVPN, именно VNI10020):
```nxos
configure terminal
evpn
 vni 10020 l2
  no route-target import auto
  route-target import 65000:9999
end
```

## Найти причину — control plane и data plane

- `show bgp l2vpn evpn` на LEAF-03: сравнить маршруты и RT для VNI10020 до/после, особенно MAC от LEAF-01.
- Проверить APP-A→APP-C: при отсутствии подходящего RT удалённые EVPN маршруты для VNI10020 не импортируются, возможен отказ L2.
- DB-B→DB-C по VNI10030 и CLIENT-A→CLIENT-B по VNI10010 должны сохраниться (другие Leaf/VNI).
- Уточнение: часть BUM/ARP ещё может проходить при прежних flood списках или stale state. Не делать вывод по одному ping.

## Откат

На LEAF-03:
```nxos
configure terminal
evpn
 vni 10020 l2
  no route-target import 65000:9999
  route-target import auto
end
```
Проверить фактический RT командой `show running-config evpn`.
