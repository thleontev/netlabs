# 01 — Отказ uplink LEAF-01 ↔ SPINE-01

**Этап:** 00 или 01  
**Задача:** отделить отказ underlay линка от потери маршрутизируемости VTEP.

> Только изолированная лаборатория EVE-NG. Изменения применяются вручную к тестовым узлам. Команды не выполнять на рабочих сетевых устройствах. Конфигурации NX-OSv 9.3(x) и реальное поведение требуют проверки на образе.

## Baseline: докажи, что всё работает до сбоя

На LEAF-01: `show ip ospf neighbors`, `show ip route 10.254.0.23`. На stage01: `show bgp l2vpn evpn summary`, CLIENT-A → CLIENT-B.

Перед изменением сохрани вывод `show running-config`, таблицы маршрутизации и результат теста. Фиксируй время и симптом, а не только успешность ping.

## Внести неисправность

На **LEAF-01**:
```nxos
configure terminal
interface Ethernet1/1
 shutdown
end
```

## Найти причину — control plane и data plane

- OSPF adjacency с SPINE-01 должна исчезнуть, с SPINE-02 остаться; `show ip route 10.254.0.23` должен показать альтернативный next-hop.
- `ping 10.254.0.23 source 10.254.0.21` после сходимости должен быть доступен.
- Stage01: BGP соседство LEAF-01→SPINE-01 может восстановиться **через второй Spine** при наличии IP-маршрута к Lo0 SPINE-01; **не утверждать**, что сессия обязательно упадёт. Состояние второго RR проверить отдельно.
- В EVE capture убедиться, что UDP/4789 продолжает идти через оставшуюся физическую связь; до сходимости возможны кратковременные потери.

## Откат

На LEAF-01:
```nxos
configure terminal
interface Ethernet1/1
 no shutdown
end
```
