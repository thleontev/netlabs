# Упражнения — OSPF Multiarea

Все задания используют **существующий** файл [`ospf_multiarea.unl`](../ospf_multiarea.unl). Изменения в настройках для выполнения заданий необязательны: сначала соберите фактические наблюдения без вмешательства в конфигурации.

| Этап | Цель | Критерий проверки |
|---|---|---|
| 1. Инвентаризация | Выявить 14 устройств, интерфейсы и area | Таблица устройств и их OSPF областей по `show ... interface` |
| 2. Area 0 | Проверить backbone и соседства | Список установленных/неустановленных соседств и причин, если есть |
| 3. ABR и маршруты | Исследовать inter-area `O IA` | Показать путь к Loopback из другой области |
| 4. Virtual link | Проверить R6 ↔ R10 через area 200 | Зафиксировать `show ip ospf virtual-links` и состояние |
| 5. Stub area 51 | Проверить особенности LSDB и default-route | Вывод LSDB/таблицы маршрутов на R11 |
| 6. NSSA area 300 | Проверить маршруты connected с R12 | Сравнить LSDB/маршруты R12 и R8 |
| 7. OSPF + EIGRP | Проверить взаимную редистрибуцию на XR2 | Вывод таблиц маршрутов XR2/R9 и происхождение префиксов |
| 8. Связность | Проверить ICMP/traceroute между областями | Протокол проверенных и недоступных Loopback с указанием причины |

## Порядок выполнения

1. Импортируйте лабу по [IMPORT-RU.md](../IMPORT-RU.md), не меняя схему сети.
2. Запишите фактические версии образов, состояние интерфейсов и доступность startup-config.
3. Для каждого этапа сохраните краткие результаты: команда → узел → ожидаемое поведение → фактический вывод → вывод.
4. Если выявляется проблема конфигурации, **зафиксируйте её как наблюдение**. Не изменяйте исходный файл в репозитории без отдельного задания.

## Команды

Общая таблица для IOSv и IOS XRv и алгоритм поиска проблем находятся в [DIAGNOSTICS.md](DIAGNOSTICS.md). При необходимости для удобства изучения конфигураций используйте [`configs/`](../configs/).

**Ограничение:** это план практических проверок, а не протокол уже успешно выполненных тестов.
