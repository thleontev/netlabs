# План развития DDoS-функций

Этот файл описывает **план расширения**, а не заявляет, что все перечисленные механизмы уже реализованы. Базовая топология `IP-TRANSIT-MULTIHOMING.unl` моделирует только маршрутизацию и IP Transit.

## Этапы

1. **00 IP Transit (выполнено)**: два upstream, клиентский eBGP multihoming, OSPF backbone, iBGP RR, route filtering, VRF-Lite, диагностика failover.
2. **01 Always-On Scrubbing (проектируется)**: два независимых POP-узла фильтрации, GRE до CE, анонс защищённого префикса только через POP, запрет обхода защиты через прямые BGP-сессии.
3. **02 On-Demand (проектируется)**: базовая маршрутизация direct, затем управляемое включение анонса через POP, переключение и безопасный rollback. Автоматический сенсор — факультативное расширение.
4. **03 Packet filtering (проектируется)**: отдельные тестовые источники legitimate/synthetic unwanted. IOSv ACL показывает статическую фильтрацию; для stateful L4, nftables и PCAP нужен дополнительный Linux QEMU node.
5. **04 Incident response (проектируется)**: отказ POP1, GRE MTU/PMTUD, BGP route leak, failed policy push, неверный возврат, регрессия фильтра и false positives.

## Принципы реализации

- Отдельный `.unl` на каждую самостоятельную стадию со своим UUID.
- Встроенные и независимо проверяемые startup-config для Cisco IOSv; VPCS настраиваются из `vpcs/`.
- Полные конфигурации каждого устройства на каждую стадию — не диффы поверх старой NVRAM.
- Схемы SVG и, при необходимости, PNG с IP планом, таблицей интерфейсов и AS.
- Сценарии по файлам с ожидаемыми состояниями, диагностикой и rollback.
- Тесты только в изолированном EVE-NG, без внешних DDoS атак и без генерации высоких pps.
- Не считать stateless ACL эмуляцией аппаратного/DPDK/SYN-proxy/L7 scrubber.

## Что пока моделировать не стоит

Коммерческие механизмы аппаратной очистки, высокоскоростную обработку DPDK, распределённое сохранение state TCP-сессий, реальные ML-детекторы, глобальный Anycast на десятках POP, специализированный WAF. Для CCNP и операционного IP-транзита важнее доказуемая маршрутизация, наличие обратного пути, BGP безопасность, GRE и контроль ACL.
